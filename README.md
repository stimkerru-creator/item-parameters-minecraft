# Item Parameters

**Item Parameters** — система индивидуальных параметров предметов и настраиваемых производственных формул для **Minecraft 1.20.1 / Fabric**. Один и тот же тип предмета может иметь разные числовые характеристики: например, две единицы руды — разную массу и чистоту. Производственный результат вычисляется по параметрам конкретных входных предметов, а не только по их типам.

Проект объединяет мод для Minecraft, независимое вычислительное Java-ядро и отдельный редактор параметров и рецептов.

## Возможности

- **Параметры отдельных предметов.** Числовые характеристики сохраняются у каждого экземпляра; объединение предметов в стаки учитывает правила параметров.
- **Производственные формулы.** Выходные характеристики рассчитываются по данным одного или нескольких входных предметов; можно задавать несколько выходных полей.
- **Редактор параметров и рецептов.** Настройка и проверка формул без ручной правки JSON, с передачей каталога в Minecraft.
- **Серверная проверка.** Сервер хранит рабочие настройки и проверяет действия с предметами и механизмами; клиент отображает характеристики и интерфейс.
- **Независимое ядро.** Вычислитель и форматы данных доступны без Minecraft и могут использоваться отдельно.

## Компоненты проекта

| Модуль | Назначение | Требуется Minecraft |
| --- | --- | --- |
| `core` | Схемы и значения параметров, компиляция и вычисление формул, числовые рецепты | Нет |
| `fabric` | Работа с ItemStack/NBT, серверный каталог, интеграция с инвентарями и механизмами | Да |
| `editor` | Самостоятельная программа для настройки параметров, рецептов и формул | Нет |

**Демонстрационный производственный механизм** расположен в `fabric/src/demo` и собирается в отдельный необязательный JAR. Он показывает работу формул и параметров в игре, но не является обязательной частью библиотеки. Основной мод работает без него и без редактора.

Готовой интеграции с обычной печью и станками сторонних модов нет: разработчик механизма подключает API библиотеки и определяет правила его слотов и операций. См. [руководство по интеграции](docs/integration.md).

## Установка

- **Мод для Minecraft:** установите Fabric Loader и Fabric API для Minecraft 1.20.1, затем поместите `item-parameters-fabric-<version>.jar` в папку `mods` клиента или сервера. Ядро и математические зависимости уже включены в мод.
- **Демонстрационный механизм (необязательно):** дополнительно поместите `item-parameters-demo-<version>.jar` той же версии в `mods`.
- **Редактор:** запустите `item-parameters-editor-<version>.jar` через Java 17. Для работы редактора Minecraft не требуется.
- **Ядро в другом Java-проекте:** подключите `dev.itemparams:item-parameters-core:<version>` через Gradle/Maven. Для этого артефакт должен быть доступен в настроенном Maven-репозитории или установлен локально; его зависимости разрешаются средствами сборки.

## Настройка параметров и формул

1. Откройте редактор и пример `examples/tutorial/Практика.ipproject`.
2. Выберите рецепт: слева расположены входные предметы и их поля, справа — выходной предмет.
3. Назначьте полям обозначения (`M1`, `M2`, `P` и т. п.) и укажите формулы. Справа от `=` записывается обозначение выходного поля.
4. Нажмите **«Рассчитать»** и проверьте значения результата.
5. Нажмите **«Передать в Minecraft…»** и выберите каталог нужной игры или сервера. Редактор создаёт резервную копию предыдущего каталога.
6. Перезапустите мир или сервер, чтобы загрузить новые настройки.

Например, у входной руды масса `M = 1000` и чистота `P = 80`:

```text
M * P / [100] * [0.95] = M
clamp(P + [10], [0], [100]) = P
[25] = H
```

Результат: **масса 760**, **чистота 90**, **твёрдость 25**. Обозначения слева от `=` читают входные значения, справа выбирается поле результата. Числа в квадратных скобках — константы. Если входов несколько, назначьте им разные обозначения, например `M1`, `M2`, `M3`.

Подробнее: [работа с редактором](docs/editor.md) · [файлы настроек](docs/configuration.md) · [математика и ограничения](docs/math.md).

## Как устроены данные и вычисления

- **Хранение значений:** каждое значение занимает 32 бита и хранится в сотых (целое число, масштабированное на 100). Представимый диапазон: от −21 474 836,48 до 21 474 836,47; отдельные поля могут иметь более узкие ограничения.
- **Идентификаторы полей:** ID определяет соответствие параметров при сохранении и загрузке. Добавление и перестановка полей не переименовывают уже существующие значения.
- **Точность:** промежуточные результаты формул не усекаются до сотых; при записи конечного значения знаки после второго отбрасываются по направлению к нулю.
- **Математические библиотеки:** используются **EvalEx 3.7.0** и **Spire 0.18.0**; отдельный процесс Python не нужен. Поддерживаемые выражения и ограничения описаны в [math.md](docs/math.md).
- **Несколько выходных полей:** все выражения одного рецепта читают исходные входные параметры. Для последовательной переработки используются отдельные рецепты.
- **Работа производственной линии:** закреплённая линия проверяет входные предметы и использует ранее рассчитанный результат. Повторный расчёт необходим при первоначальной настройке или перенастройке.
- **Кэширование:** один `Workspace` хранит одну комбинацию входов, а не глобальный кэш всех вариантов. Изменяемые значения и `Workspace` не должны совместно использоваться параллельными владельцами.

Дополнительно: [API ядра](docs/core-api.md) · [архитектура](docs/architecture.md).

## Сборка и проверки

Для сборки требуется **JDK 17 или новее**.

**Windows (PowerShell):**

```powershell
.\gradlew.bat build
```

**Linux / macOS:**

```bash
./gradlew build
```

Готовые JAR собираются в корневой каталог `build/libs/`. Версия проекта задаётся в `gradle.properties`.

Только `core` и `editor`, без конфигурации Fabric Loom и загрузки Minecraft:

```bash
./gradlew -Pstandalone=true build
```

Запуск редактора из исходников:

```bash
./gradlew -Pstandalone=true :editor:run
```

Запуск собранного редактора:

```bash
java -jar build/libs/item-parameters-editor-<version>.jar
```

Задача `build` запускает JUnit-тесты, проверку независимости `core` и проверки Fabric без необязательных компонентов. Ресурсоёмкие замеры производительности выполняются отдельно и не входят в стандартную сборку.
