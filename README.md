# Item Parameters

Библиотека индивидуальных числовых параметров и производственных формул для Minecraft **1.20.1 / Fabric / Java 17**. Одному типу предмета можно назначить поля; каждый экземпляр хранит собственные значения. Формула преобразует параметры одного или нескольких входов в один выходной набор.

Проект состоит из трёх модулей в одном репозитории:

| Модуль | Назначение | Нужен Minecraft |
|---|---|---|
| `core` | Массив параметров, схемы, компиляция и вычисление формул, числовые рецепты | Нет |
| `fabric` | ItemStack/NBT, серверный каталог, подключение к инвентарям и механизмам | Да |
| `editor` | Отдельная программа со списками параметров и формулами | Нет |

Тестовый станок находится в `fabric/src/demo` и собирается **отдельным необязательным JAR**. Основа работает без него и без редактора. Старые имена Java-пакетов и классов сохранены.

## Что устанавливать

- В Minecraft: `item-parameters-fabric-<version>.jar` и Fabric API. Числовое ядро и математические зависимости уже вложены в этот JAR.
- Для учебного станка: дополнительно `item-parameters-demo-<version>.jar` той же версии.
- Для настройки вне игры: `item-parameters-editor-<version>.jar`, запуск через Java 17.
- Для другой Java-системы: обычная зависимость `dev.itemparams:item-parameters-core:<version>`; Minecraft и Fabric ей не нужны. Core JAR обычный, его зависимости разрешаются через Gradle/Maven.

Здесь нет готовой интеграции с обычной печью или станками других модов. Их автор подключает API и правила слотов своего механизма; [инструкция интеграции](docs/integration.md) описывает границу ответственности.

## Сборка

На Windows:

```powershell
.\gradlew.bat build
```

На Linux/macOS:

```sh
./gradlew build
```

Готовые JAR собираются в корневую папку `build/libs/`. Текущая версия для разработки задаётся в `gradle.properties`.

Только Java-ядро и редактор, без конфигурации Loom и загрузки Minecraft:

```sh
./gradlew -Pstandalone=true build
```

Запуск редактора из исходников:

```sh
./gradlew -Pstandalone=true :editor:run
```

Либо после сборки: `java -jar build/libs/item-parameters-editor-<version>.jar`.

## Настройка без программирования

1. Откройте редактор и пример `examples/tutorial/Практика.ipproject`.
2. Выберите рецепт. Слева находятся входные предметы и их поля, справа — выходной предмет.
3. Назначьте полям обозначения, например `M1`, `M2`, `P`, и впишите формулы. Справа от `=` указывается поле **выхода**.
4. Нажмите **«Рассчитать»**, проверьте результат.
5. Нажмите **«Передать в Minecraft…»**, выберите папку нужной игры/сервера. Редактор сохраняет резервную копию предыдущего каталога.
6. Перезапустите мир/сервер для загрузки настроек.

Например, масса руды `M = 1000`, чистота `P = 80`:

```text
M * P / [100] * [0.95] = M
clamp(P + [10], [0], [100]) = P
[25] = H
```

На выходе: масса **760**, чистота **90**, твёрдость **25**. Числа в квадратных скобках — константы; обозначения слева читают вход, справа выбирают поле выхода. Для нескольких предметов назначайте различимые обозначения, например `M1`, `M2`, `M3`.

## Контракт данных и производства

- Значение занимает 32 бита и хранится в сотых (`int32 × 100`): от −21 474 836,48 до 21 474 836,47. Поля могут иметь более узкий диапазон.
- ID поля определяет соответствие при сохранении и загрузке; перестановка или добавление полей не переименовывает существующие значения.
- Промежуточные результаты до сотых не усекаются. На записи результата дробные знаки после второго отбрасываются к нулю.
- Математику выполняют готовые **EvalEx 3.7.0 + Spire 0.18.0**. Отдельный Python-процесс не требуется. Поддерживаемая область формул описана в [math.md](docs/math.md).
- Все назначения рецепта читают исходные входы. Последовательные производственные этапы — отдельные рецепты.
- Закреплённая линия проверяет входы, использует сохранённый результат и создаёт выходной предмет. Вычислитель нужен при первоначальном расчёте или перенастройке.
- Один `Workspace` запоминает одну комбинацию; глобального кэша всех вариантов нет. Workspace и изменяемые значения не передаются между параллельными владельцами.

## Проверки и разработка

`build` запускает JUnit-проверки модулей, проверку независимости ядра и проверку Fabric без необязательных компонентов. Тяжёлые измерения производительности помечены отдельно и в обычный `build` не входят.
