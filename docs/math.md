# Формулы, точность и ограничения

Математический синтаксис, AST и выполнение выражения предоставляет **EvalEx 3.7.0**. Дроби, корни и точные сравнения выполняет **Spire 0.18.0**, типы `Rational` и `Algebraic`. Код проекта связывает ID/символы с массивами, подключает операции библиотек, проверяет допустимость выражения и записывает результат. Собственного калькулятора или второго backend здесь нет.

## Операции

Поддерживаются `+`, `-`, `*`, `/`, `^`, унарные знаки и скобки, функции `sqrt(x)`, `pow(x, p)`, `root(x, n)`, `min(a, b)`, `max(a, b)`, `clamp(x, min, max)`.

Приоритеты: `-2^2 = -4`, `2^-2 = 0.25`, `2^3^2 = 512`. Умножение записывается явно: `2 * x`, а не `2x`. В технических формулах поля записываются `${role::namespace:field}`; при одном legacy-входе — `${namespace:field}`. В редакторе используются назначенные символы и номера строк, см. [editor.md](editor.md).

Степень и степень корня должны быть доказуемыми рациональными числами. `pow(27, 2/3)` и `root(-8, 3)` поддерживаются. `pow(2, sqrt(2))` отклоняется: трансцендентные результаты не заменяются приблизительным числом. Отрицательная база с дробной степенью, отрицательный квадратный корень, деление на ноль, `0^0` и обратный диапазон clamp вызывают ошибку.

## Точность

Текстовые числа и входные сотые поступают в библиотечную точную арифметику без промежуточного `double`. `(1/3)*3` даёт 1; `sqrt(2)*sqrt(8)` даёт 4. Промежуточные результаты до сотых не усекаются.

Только окончательный результат поля умножается на 100, дробная часть отбрасывается **к нулю**, затем проверяются int32 и диапазон поля: `1.299 → 1.29`, `-1.299 → -1.29`. Для алгебраического результата проверяется точный целый интервал; epsilon не используется. Неподтверждённый результат вызывает ошибку.

Методы `evaluateRaw*` и `evaluateStored*` предназначены для хранения. `evaluateApproximateDecimal*` — диагностическое представление на 128 значащих цифр; его не следует кодировать обратно для производства.

## Компиляция и ресурсы

Формула компилируется один раз на определение рецепта. Полностью постоянные выражения вычисляются при компиляции. Повторное выполнение использует готовый AST; все входные массивы ради каждой формулы не копируются.

Пределы: 8192 символа, 4096 узлов, 128 уровней вложенности; один числовой литерал — до 4096 бит, общий бюджет различных литералов — 16384 бита. Числитель и знаменатель рациональной степени ограничены 10000, кроме точных безопасных случаев 0 и 1. Дополнительно проверяется рост целой степени.

Точная алгебраическая арифметика может быть дорогой на сложных выражениях. Эти ограничения не обещают фиксированное время выполнения любой допустимой формулы. Расчёт настройки не следует выполнять каждый серверный тик; механизм должен повторно использовать подтверждённый выход.
