# Файлы предметов и рецептов

Настройки загружаются на сервере при запуске из `config/itemparams/`. Можно хранить один объект на файл или несколько в массиве; подпапки поддерживаются. На каждый индивидуальный экземпляр предмета отдельный JSON не создаётся.

Готовый минимальный каталог находится в `examples/catalog`. Скопируйте **его содержимое** в `config/itemparams/`, чтобы получить `items/` и `recipes/` непосредственно внутри этой папки. Если основной каталог уже настроен, сначала сохраните резервную копию и проверьте уникальность ID. В обычной работе удобнее [редактор](editor.md).

## Назначение параметров предмету

`items/raw_iron.json`:

```json
{
  "version": 1,
  "item": "minecraft:raw_iron",
  "fields": [
    {"id": "factory:mass", "default": 1000, "min": 0},
    {"id": "factory:purity", "default": 80, "min": 0, "max": 100}
  ]
}
```

- `version` — версия **формата файла**, сейчас 1. Это не версия мода и не номер рецепта.
- `item` — ID уже существующего предмета. Для предмета другого мода укажите его ID, например `othermod:ore`; соответствующий мод должен быть установлен.
- `fields` — список параметров этого предмета.
- `id` — постоянный технический ID поля. От него зависит сохранность соответствия данных; видимое название/символ редактора можно менять отдельно.
- `default` — начальное значение. `min` и `max` — необязательные границы. Все эти числа задаются в обычных единицах, максимум с двумя знаками после точки.

Сокращение `"factory:mass"` вместо полного описания означает default 0 и полный диапазон int32-сотых. Чтобы задать число, название ID и диапазон явно, используйте полное описание, как выше.

У выходного предмета тоже должна быть схема: какие поля существуют и чему равны до применения правил рецепта. Пример `items/iron_ingot.json` объявляет массу, чистоту и твёрдость.

## Рецепт

`recipes/smelting.json`:

```json
{
  "version": 1,
  "id": "factory:smelting",
  "inputs": {"ore": "minecraft:raw_iron"},
  "output": {"item": "minecraft:iron_ingot", "count": 1},
  "assignments": {
    "factory:mass": "${ore::factory:mass} * ${ore::factory:purity} / 100 * 0.95",
    "factory:purity": "clamp(${ore::factory:purity} + 10, 0, 100)",
    "factory:hardness": "25"
  }
}
```

`id` — уникальное имя рецепта. `inputs` связывает выбранное разработчиком имя роли с предметом. `output` задаёт один выходной Item ID и число единиц. В `assignments` слева указан **ID поля выхода**, справа — формула его нового значения. `${ore::factory:mass}` читает поле `factory:mass` именно из роли `ore`.

В техническом JSON числа обычные (`25`, `0.95`), без квадратных скобок редактора. Для нескольких предметов добавьте роли, например `plate`, `bolt`; `${plate::factory:mass}` и `${bolt::factory:mass}` независимы. Числовое ядро не фиксирует число ролей. Каталог ограничен 64 ролями на рецепт, учебный станок — четырьмя слотами.

Правила подготовки выхода:

1. Начальные значения его схемы; `base` может их заменить.
2. `copy_common_from: "ore"` переносит поля с совпадающими ID из указанного входа.
3. `transfers` назначает явный перенос: `"factory:mass": {"input": "ore", "field": "factory:mass"}`.
4. `assignments` задаёт окончательные вычисляемые поля.

Все формулы читают первоначальные входы. Поля без назначения сохраняют результат выбранных правил переноса/defaults. Неизвестное поле отклоняется при загрузке; опечатка не создаёт новое поле.

Несколько рецептов в одном файле: `{"version":1,"recipes":[ ... ]}`. Несколько предметов: `{"version":1,"items":[ ... ]}`. При разделении файлов переносите записи, а не дублируйте их ID. Некорректный каталог не публикуется частично.

## Откуда берутся значения в игре

Основа материализует настроенные значения на сервере для предметов в инвентарях игроков и открытых контейнерах. Это не регистрация новых Item ID и не обработчик каждого события добычи в мире. Для немедленного назначения при собственном дропе, создании или хранении вне этих инвентарей вызывающий мод использует `ItemParameterStorage` / `ConfiguredItemParameters`.

Если существующие поля есть в корректном NBT, их значения сохраняются; новые поля получают defaults. При нормализации активной схемы удалённые поля исключаются, прочие NBT-теги предмета сохраняются. Не меняйте технический ID, если хотите сохранить старое значение как то же поле.

Производственный рецепт сам по себе не подключается к ванильной печи. Выберите его в demo-станке либо вызовите API из своего механизма. Изменённый каталог загружается после перезапуска мира/сервера; Java-интеграция может явно вызвать предусмотренную загрузку с проверкой.
