# Границы модулей

Один репозиторий и одна версия сохраняют совместимость данных, API, редактора и Fabric-адаптера. Это три Gradle-проекта, которые выпускают независимые артефакты; отдельные Git-репозитории для этого не требуются.

```text
core ← editor
  ↑
fabric ← optional demo (отдельный JAR из fabric/src/demo)
```

`core` содержит `ParameterSchema`, `ParameterValues`, `FormulaCompiler`, `ParameterRecipe` и привязку пользовательских обозначений к ID. Математический backend остаётся EvalEx/Spire. Небольшой `StrictJson` также общий для редактора и адаптера; поэтому core зависит от Gson. Он не знает ItemStack, NBT, мир, слоты и Swing.

`fabric` зависит от core. Здесь остаются ItemStack/NBT, каталог существующих Item ID, материализация начальных значений и серверная интеграция. `ProductionRecipe` — сохранённый Minecraft API одного входа; `ConfiguredItemRecipe` — адаптер именованных входов. Оба используют существующий числовой движок. Собственной второй реализации вычислителя нет.

`editor` зависит от core. Он сохраняет проект, связывает символы с полями, предварительно рассчитывает формулы и экспортирует каталог. Настройки и готовые проекты не нужны игровому серверу для выполнения уже закреплённой операции.

Demo — пример владельца слотов и сохранённой пары вход/выход. Он намеренно остаётся source set внутри Fabric-проекта: использует тот же Minecraft toolchain и собирается отдельным JAR. Для числового ядра, редактора и основного мода этот JAR не требуется.

## Почему не два репозитория

Сейчас изменения формата и API затрагивают редактор и адаптер вместе. В одном репозитории их проверяет одна сборка. Core уже имеет самостоятельные Maven-координаты, обычный POM и команду сборки без Minecraft. Отдельный репозиторий понадобится только при независимом сопровождении и графике выпусков; для повторного использования библиотеки он не нужен.

## Упаковка

- Core публикуется как обычная Java-библиотека с зависимостями в POM.
- Fabric JAR включает core и математические runtime-зависимости как вложенные библиотеки. Gson предоставляется Minecraft.
- Исполняемый editor JAR включает core и зависимости для самостоятельного запуска. Thin JAR используется внутри Gradle между проектами.
- Основной Fabric JAR не включает станок, его ресурсы или классы редактора.

Числовые API-пакеты и публичные имена классов сохранены. Разделение модулей не меняет формат `int32 ×100`, JSON, `.ipproject`, NBT или семантику формул.
